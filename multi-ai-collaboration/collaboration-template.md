# 协作区模板（5 分区）

> 一个标准化的共享协作空间。所有 AI 启动时先读它，就知道当前目标、历史决策、待办、各自状态和最新产出。

## 为什么用固定分区

固定的分区结构让"读协作区"这个动作变得**零认知成本**：AI 不在茫茫文档里找信息，而是知道目标在哪个区、决策在哪行。分区固定后，可以正确地与信息素标记协议（见 `stigmergy-protocol.md`）配合——甚至可以让一个监控脚本自动扫描特定分区。

## 模板结构

```
┌──────────────────────────────────────────┐
│  📌 当前目标                              │
│  （一句话描述本周目标，足够具体到可判断完成）   │
├──────────────────────────────────────────┤
│  ✅ 决策记录（最新 → 最旧）                 │
│  [日期] 决策内容 | 决策者 | 依据             │
│  [日期] 决策内容 | 决策者 | 依据             │
├──────────────────────────────────────────┤
│  📋 待办事项                              │
│  [WHO] [WHAT] [NEXT] [状态]               │
│  [WHO] [WHAT] [NEXT] [状态]               │
├──────────────────────────────────────────┤
│  📊 当前状态                              │
│  角色A: ... | 角色B: ... | 角色C: ...      │
├──────────────────────────────────────────┤
│  📦 最新产出（链接）                       │
│  [日期] 产出标题 | 链接 | 谁产出            │
└──────────────────────────────────────────┘
```

## 各分区职责

| 分区 | 是谁写 | 是谁读 | 目的 |
|------|--------|--------|------|
| 当前目标 | 协调者 | 所有 AI | 让大家知道"往哪走" |
| 决策记录 | 做决策的 AI | 所有 AI | 避免重复决策、记录依据 |
| 待办事项 | 任意 AI（顺手更新） | 接手方 | 交接不失控 |
| 当前状态 | 各 AI 自报 | 协调者/他 AI | 谁卡住、谁进行中一目了然 |
| 最新产出 | 产出方 | 所有 AI | 知道有什么可复用 |

## 约定

- **待办行格式固定**：`[WHO] [WHAT] [NEXT] [状态]`，`WHO` 用角色名而非个人名，`NEXT` 明确指出"下一个谁来做什么"。
- **决策记录只追加、不覆盖**：保持"最新 → 最旧"顺序，便于追溯当时依据。
- **拿不准要不要写进协作区的，先写**：成本低，但能极大降低其他 AI 的检索成本。

## 落地注意

- 协作区是一份**共享权威文档**，不是日志草稿。写之前想清楚"这个信息是否值得别人花费一次读取"。
- 当文档变大时，配合轻量 RAG（按标签检索）而非全量读取——见 `competitive-evolution.md` 的补充说明，或项目主 README 的"轻量 RAG"提示。
