# 角色架构设计

> 多 AI 协作的前提是**分工清晰、边界明确**。本文件给出一个经过验证的 5 角色分工模板，以及每个角色的职责与边界。

## 5 角色分工模板

```
┌─────────────────────────────────────────────┐
│ 协调者  Centroid                            │
│  定目标、分配任务、收尾验收                  │
├─────────────────────────────────────────────┤
│ 情报Agent  Intelligence                    │
│  搜集、整理、研判外部信息                    │
├─────────────────────────────────────────────┤
│ 内容Agent  Content                          │
│  产出创意/文案/方案                         │
├─────────────────────────────────────────────┤
│ 执行Agent  Execution(如 CEO 视角)           │
│  把方案拆解落地、跟进进度、交付              │
├─────────────────────────────────────────────┤
│ 分身Agent  Twin(守门人)                     │
│  审核标准、守住红线、校准方向                │
└─────────────────────────────────────────────┘
```

## 各角色职责与边界

| 角色 | 该做什么 | 不该做什么 |
|------|---------|-----------|
| 协调者 | 定目标、分配、统筹、验收 | 不代替执行；不绕过分身做最终质量把关 |
| 情报Agent | 事实输入、竞品/市场研判 | 不做拍板；不把倾向性当事实 |
| 内容Agent | 创意产出、多版本方案 | 不独自承诺交付；不伪造来源 |
| 执行Agent | 拆解、调度、推进、交付 | 不替协调者分配；不越权决策 |
| 分身Agent | 审核标准、红线、方向校准 | 不做执行；只在需要校准/仲裁时出手 |

## 设计原则

1. **角色 = 职责边界，不是 "人"**：角色是能力槽位，可由不同 AI 实例或同一实例在不同会话扮演。
2. **边界比能力更重要**：明确"谁不干什么"比"谁干什么"更能防住协作失控。
3. **守门人必须存在**：否则"共识"会滑向"平庸"，"执行"会滑向"越权"。

## 落地

- 将每个角色的职责写成一段"岗位说明书"（即系统提示词），挂到对应会话。
- 配合协作区模板（`collaboration-template.md`）用角色名打标，信息素标记（`stigmergy-protocol.md`）才能正确路由到 `NEXT`。
- 数字分身的审核/红线逻辑见 `digital-twin-pattern/` 目录，可直接复用。

## 角色数量怎么定

- 起步 3 人就够（协调 + 情报/内容 + 执行），别一上来铺 5 个。
- 只有出现"确实需要单独一个角色把关"的需求时再加分身或更多情报位。
- 加角色的前置判断：有没有"不加就明显卡壳"的具体场景？没有就先不加。
