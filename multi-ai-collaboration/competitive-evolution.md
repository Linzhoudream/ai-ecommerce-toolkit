# 竞争演化机制

> 对关键决策，不让多个 AI "开会达成共识"，而是让它们**各自独立求解**，再取最优或交叉重组。"共识带来平庸，对抗带来进化。"

## 触发场景

适用于需要**多样性**的任务：
- 内容创意方向
- 方案策划
- 产品定位 / 玩法设计

不适用于：
- 数据统计、执行类任务（这类只需"做对"即可，不需要多方案）

## 机制流程

```
阶段1  并行独立求解
   4 个 AI 各自独立解决同一问题，互不参考，产出 4 个方案

阶段2  集中评审
   对 4 个方案做维度对比（如：可行性/创新/成本/风险）

阶段3  择优或重组
   选项A：选定最优方案 1 个
   选项B：交叉重组——把 A 的思路 + B 的落地 + C 的风险控制拼成一个"
版本2"
```

## 对比表格模板

| 方案 | 可行性 | 创新度 | 成本 | 风险 | 评价 |
|------|--------|--------|------|------|------|
| 方案A | | | | | |
| 方案B | | | | | |
| 方案C | | | | | |
| 方案D | | | | | |

## 为什么有效

- 共识型协作容易"随大流"，产出的往往是最大的公约数（平庸）
- 独立求解保住了每个视角的**差异性**，交叉重组能得到单无人能独自想出的组合方案
- 特别适合创意发散阶段，把"谁对谁错"变成"哪个最优、怎么拼"

## 注意事项

- **不参与竞争演化**：可量化的执行 / 数据类任务，一个人做对就行，别浪费算力。
- **评审不能缺席**：择优或重组需要有一个"守门人"（协调者或数字分身），否则会陷入方案间争论。
- **成本权衡**：N 个 AI 并行求解 = N 倍算力，只对"值得多样化"的关键决策用。

## 与超时降级配合

若参与演化的某个 AI 超时（见 `timeout-fallback.md`），方案数量减少但仍可评审，不影响主流程——这正是降级机制提供的韧性。
