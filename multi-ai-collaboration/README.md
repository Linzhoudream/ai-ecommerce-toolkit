# Multi-AI Collaboration Framework（多 AI 协作框架）

> 一套经过真实验证的多 AI 协作方法论。回答一个核心问题：**当多个 AI 智能体要一起完成任务时，如何不靠"开会"、不用重型实时系统，也能高效、稳定地协作？**

## 为什么需要这个框架

大多数"多 AI 协作"的讨论都停留在概念层：给每个 AI 定个角色、然后想象它们能实时对话。但真实落地时会撞上几个硬问题：

- 共享上下文文件越来越大，每个 AI 启动时读不完、也读不动
- 每次都"开会讨论"不现实，AI 没有人类那种即时响应义务
- 一个 AI 不响应，整个流程就卡死
- 为了让 AI 能互相调用而搭建复杂平台，成本高、性价比低

本框架给出**一套分阶段、可验证、低成本起步**的落地路径，核心洞察是：**AI 协作不需要"实时通讯"，靠"环境标记"就足以驱动协作。**

## 核心概念速览

| 概念 | 作用 |
|------|------|
| 协作区模板 | 一个标准化的共享空间，所有 AI 启动时读一次就知道"现在该做什么" |
| 信息素标记（Stigmergy） | AI 在共享文档留下结构化标记，其他 AI 读到标记自动触发下一步 |
| 超时降级 | 不依赖"约定时效"，用一个 AI 超时后的兜底策略保证流程不断 |
| 竞争演化 | 关键决策让多个 AI 各自独立求解，取最优，对抗"共识带来的平庸" |
| Memory / RAG / Tool Use | 跨会话记忆、检索式加载、工具调用——协作闭环的三大缺失层 |

## 快速上手（阶段 0：零成本当天见效）

1. 建立一个标准化的**协作区文档**，固定 5 个分区（目标 / 决策记录 / 待办 / 当前状态 / 产出链接）。
2. 约定每个 AI 启动时先读协作区 → 按标记行动 → 干完写回标记 → 下一个 AI 接力。
3. 给每个产出文件加**结构化标签**，AI 按标签检索而非全量读取（轻量 RAG）。
4. 让 AI 之间靠**信息素标记**互相触发，不靠实时对话。

具体模板见 [`collaboration-template.md`](collaboration-template.md)。

## 何时升级

先跑异步模式（阶段 0–1）。只有当**异步优化后仍无法解决的目标场景**被明确证明存在，才考虑进入中成本的实时协作平台阶段（阶段 2）。详见各文档。
