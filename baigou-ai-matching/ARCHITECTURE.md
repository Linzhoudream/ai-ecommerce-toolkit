# 白沟箱包 AI 匹配台 · 架构说明（v2.0）

## 1. 项目结构

```
baigou-ai-matching/
├── index.html      # 页面壳：完整UI布局（分类面板+AI对话+信息流+弹窗）
├── styles.css      # 紫色品牌视觉主题，支持深色模式，全响应式
├── rules.js        # 核心规则引擎：帖子解析 + AI翻译 + 智能匹配 + 筛选
├── app.js          # UI交互层：AI追问对话流 + 发布向导 + 匹配弹窗 + 状态管理
└── ARCHITECTURE.md # 本文件
```

> 设计原则：**业务规则与 UI 分离**。改翻译/匹配逻辑只动 `rules.js`，改界面只动 `app.js`/`styles.css`。

## 2. 功能板块总览

### 板块1：核心主营业务分类（12个细分入口）
- **加工交易**：放加工、接加工、接单
- **货源商贸**：招供货商、我要供货、箱包合作、积压品
- **物料设备**：箱包设备、箱包辅料、回收辅料
- **电商配套**：电商服务、免费发布

### 板块2：人力资源（5项服务）
企业招聘、招小时工、个人求职、上门服务、教育培训

### 板块3：本地不动产 & 商业转让（5项服务）
房屋租赁、二手房、整体转让、供求信息、车辆信息

### 板块4：生活商务配套（5项服务）
家政服务、商业服务、企业登记、找回密码、诈骗举报

### 板块5：AI产业助手（右侧面板）
- 智能追问对话（识别角色→品类→细节）
- 快捷操作入口（放加工/接加工/找供货商/供货物料）
- 自由文本输入（NLP解析用户意图）

### 板块6：AI智能发布向导（4步弹窗）
步骤1：选择角色 → 步骤2：选择品类 → 步骤3：填写详情 → 步骤4：AI翻译+确认发布

### 板块7：多维筛选 + 信息流
按角色、品类、数量、交期筛选供需帖子，每帖含AI翻译卡和匹配按钮

## 3. 数据流

### 3.1 发布流程
```
用户打开发布向导
    │
    ▼
步骤1: 选择角色（加工厂/采购商/辅料供应商/电商卖家）
    │
    ▼
步骤2: 选择品类（女包/双肩包/行李箱/...）
    │
    ▼
步骤3: 填写数量、交期、价格、备注
    │
    ▼
步骤4: AI生成翻译卡（卡点+建议+风险）→ 确认发布
    │
    ▼
帖子加入 posts[] → 渲染信息流 → 自动匹配
```

### 3.2 AI对话流程
```
用户输入："我有一批女包要做"
    │
    ▼
parsePost() 识别角色=采购商, 品类=女包
    │
    ▼
AI追问：确认角色 → 确认品类 → 询问数量/交期
    │
    ▼
引导进入发布向导 / 直接查看匹配
```

### 3.3 匹配流程
```
runMatch(targetPost, allPosts)
    │
    ├── 角色互补匹配（权重10：采购商↔加工厂）
    ├── 品类匹配（权重5：同品类）
    ├── 数量匹配（权重3：范围交叉）
    └── 交期匹配（权重2：可协商）
    │
    ▼
返回按匹配度排序的 Top 5 结果
```

## 4. 核心函数说明（rules.js）

| 函数 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `parsePost(raw)` | 帖子字符串 | `{role, category, quantity, delivery, price, raw}` | 正则+NLP提取角色/品类/数量/交期/价格 |
| `translate(parsed)` | parsePost 输出 | `[{pain, advice, risk}, ...]` | 根据角色+品类+数量+交期生成大白话建议卡 |
| `runMatch(target, all)` | 目标帖 + 全部帖子 | `[{post, score, reasons, matchPercent}, ...]` | 多维度加权匹配，返回Top 5 |
| `filterPosts(posts, filters)` | 帖子数组 + 筛选条件 | 过滤后的帖子数组 | 按角色/品类/数量/交期筛选 |
| `generateId()` | 无 | 唯一ID字符串 | 基于时间戳+随机数 |
| `formatTime(ts)` | 时间戳 | "刚刚"/"3小时前"/"2天前" | 友好的时间显示 |

## 5. AI 增强插槽（如何接真实 LLM）

当前 `translate(p)` 内部是硬编码规则。要换成 LLM，只需把函数体改为：

```js
async function translate(p) {
  const prompt = `你是一位白沟箱包产业顾问。请根据以下帖子信息，用大白话给出"卡点+建议+风险"。
角色：${p.role}，品类：${p.category}，数量：${p.quantity}，交期：${p.delivery}。
原帖：${p.raw}`;
  const resp = await fetch('你的 LLM API 地址', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ prompt })
  });
  const data = await resp.json();
  return data.cards; // 返回 [{pain, advice, risk}, ...]
}
```

同样，`parsePost()` 和 AI对话流程也可以接入 LLM 实现更精准的意图识别。

## 6. 如何添加新规则

在 `rules.js` 的 `translate(p)` 中新增 `if` 分支即可。例如增加"直播带货"相关规则：

```js
if (/直播|带货主播/.test(p.raw)) {
  cards.push({
    pain: "直播带货退货率高，库存压力大",
    advice: "建议小批量测款，爆款再追单",
    risk: "跟风爆款容易扎堆，利润空间被压缩"
  });
}
```

## 7. 与白沟河网的对比

| 维度 | 白沟河网（传统） | 白沟AI匹配台（本平台） |
|---|---|---|
| 发布方式 | 自由发帖，信息参差不齐 | AI 4步向导，引导补齐关键信息 |
| 匹配方式 | 被动浏览 | AI主动撮合，多维度加权匹配 |
| 产业分析 | 无 | AI翻译卡：卡点+建议+风险 |
| 用户门槛 | 高（需自己写帖） | 低（AI对话+引导式发布） |
| 移动适配 | 基础适配 | 全响应式+底部导航栏 |
| 智能助手 | 无 | AI产业助手，实时对话 |
| 诈骗防护 | 举报入口 | 内置风险提示 |

## 8. 红线与边界

- 本 MVP 只做**信息翻译与匹配辅助**，不碰货、不撮合抽成、不经营。
- 数据来源：当前使用内置样本；若接入真实白沟河网数据，需自行解决授权与合规抓取。
- AI翻译建议仅供参考，不构成商业决策依据。
- 诈骗举报为入口引导，实际处理需接入人工审核流程。
